# Поликлиника — регистратура и управление клиникой

Полноценное небольшое веб-приложение для записи на приём: недельное расписание, картотека пациентов, проверка занятости слотов на сервере и защищённая панель администратора для ведения врачей, пациентов и журнала записей.

## Возможности

- Недельный календарь с переходом между неделями и цветовой маркировкой врачей.
- Создание записи с проверкой существования врача и пациента, даты, времени и занятости **на сервере**.
- Автоматическая проверка свободных слотов для выбранных врача и даты; повторная проверка при сохранении защищает и от одновременной записи.
- Запрет двойной записи одного пациента на одно время.
- Поиск врачей и пациентов; добавление пациентов из регистратуры.
- Защищённая паролем панель администратора: добавление, редактирование, архивирование и восстановление врачей и карточек пациентов; журнал записей с отменой приёма.
- Архив вместо физического удаления сохраняет историю приёмов; архивные записи не доступны для новых приёмов.
- Миграция исходной SQLite-базы при первом запуске. Если база пустая, создаются демонстрационные данные.
- Интерфейс адаптирован для мобильных экранов.

## Стек и структура

- Python 3.10+ и Flask
- SQLite, отдельная сборка фронтенда не нужна
- HTML, CSS и vanilla JavaScript

```text
polyclinic/

├── requirements.txt
```

## Запуск

```bash
python -m venv .venv
# macOS / Linux
source .venv/bin/activate
# Windows PowerShell: .venv\Scripts\Activate.ps1

pip install -r requirements.txt
```

Перед запуском задайте пароль администратора и постоянный секрет Flask-сессии. **Не используйте примеры ниже как пароли для реальной клиники.**

macOS / Linux:

```bash
export ADMIN_PASSWORD='задайте-длинный-уникальный-пароль'
export SECRET_KEY="$(python -c 'import secrets; print(secrets.token_hex(32))')"
python app.py
```

Windows PowerShell:

```powershell
$env:ADMIN_PASSWORD = 'задайте-длинный-уникальный-пароль'
$env:SECRET_KEY = python -c "import secrets; print(secrets.token_hex(32))"
python app.py
```

Откройте <http://localhost:5000>, затем нажмите **«Вход администратора»** и введите заданный пароль. Без `ADMIN_PASSWORD` регистратура и запись работают, но административный вход отключён. Для HTTPS-развёртывания установите `SESSION_COOKIE_SECURE=1`, настройте HTTPS и задайте постоянные случайные `SECRET_KEY` и `ADMIN_PASSWORD` через менеджер секретов окружения.

### Конфигурация

| Переменная | Назначение |
|---|---|
| `ADMIN_PASSWORD` | Пароль администратора. Если переменная не задана, операции панели администратора закрыты. |
| `SECRET_KEY` | Ключ подписи сессий Flask; задайте постоянное случайное значение. Если не задан, генерируется новый ключ при старте и активные сессии сбрасываются при перезапуске. |
| `CLINIC_DB_PATH` | Путь к SQLite-файлу. По умолчанию используется `clinic.db` рядом с `app.py`. |
| `HOST` | Адрес прослушивания; по умолчанию `0.0.0.0`. |
| `PORT` | Порт HTTP-сервера; по умолчанию `5000`. |
| `SESSION_COOKIE_SECURE` | При значении `1` браузер отправляет cookie только по HTTPS. Для локального HTTP оставьте `0`. |

## API

### Регистратура

| Метод | Путь | Назначение |
|---|---|---|
| `GET` | `/api/doctors` | Активные врачи |
| `POST` | `/api/doctors` | Добавить врача (только администратор) |
| `PATCH` | `/api/doctors/<id>` | Изменить ФИО или специализацию (администратор) |
| `DELETE` | `/api/doctors/<id>` | Архивировать врача (администратор, история сохраняется) |
| `POST` | `/api/doctors/<id>/restore` | Восстановить врача из архива (администратор) |
| `GET` | `/api/patients` | Активные пациенты |
| `POST` | `/api/patients` | Добавить пациента |
| `GET` | `/api/schedule?week_start=YYYY-MM-DD` | Расписание недели, начинающейся с указанной даты |
| `GET` | `/api/availability?doctor_id=1&date=YYYY-MM-DD` | Свободные и занятые слоты врача на дату |
| `POST` | `/api/appointments` | Создать запись `{doctor_id, patient_id, date, time}` |

### Панель администратора

| Метод | Путь | Назначение |
|---|---|---|
| `GET` | `/api/admin/session` | Статус настройки и текущей сессии |
| `POST` | `/api/admin/login` | Вход `{password}` |
| `POST` | `/api/admin/logout` | Выход |
| `GET` | `/api/admin/summary` | Счётчики для сводки |
| `GET` | `/api/admin/doctors` | Врачи, включая архивных |
| `GET` | `/api/admin/patients` | Пациенты, включая архивных |
| `GET` | `/api/admin/appointments?scope=upcoming` | Журнал (до 100 записей); `scope=all` включает историю |
| `PATCH` / `DELETE` | `/api/patients/<id>` | Изменить или архивировать карточку пациента |
| `POST` | `/api/patients/<id>/restore` | Восстановить карточку |
| `DELETE` | `/api/appointments/<id>` | Отменить приём |

Административные изменения используют сессию и CSRF-токен. Браузер и сервер общаются с одного источника; токен автоматически передаётся интерфейсом.

## Проверки

```bash
python -m unittest discover -s tests -v
```

Тесты используют временную базу и не меняют `clinic.db`.

## Важно для реального использования

Это компактная основа для локального прототипа, а не сертифицированная медицинская информационная система. Перед подключением реальных данных необходимы HTTPS, надёжный менеджер секретов, резервное копирование и контроль доступа сотрудников; проверьте требования по защите и обработке персональных медицинских данных в вашей юрисдикции. Не публикуйте базу `clinic.db` в открытом доступе.
